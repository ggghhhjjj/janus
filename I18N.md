# Internationalization (i18n) System

This project uses a **custom runtime i18n system** with runtime translation lookup. All translations are stored directly in TypeScript, providing a simple, type-safe approach without the complexity of build-time XLIFF processing.

## Architecture

```
src/app/services/translations.generated.ts
     ↓
i18n.service.ts (Runtime translation lookup)
     ↓
Components using i18n.translate() in templates
```

## Translation Source of Truth

**`src/app/services/translations.generated.ts`** is the single source of truth for all translations.

This file contains:
```typescript
export interface TranslationMap {
  [key: string]: { [locale: string]: string };
}

export const GENERATED_TRANSLATIONS: TranslationMap = {
  "formLabelDate": { "en": "Date", "bg": "Дата" },
  "formLabelTime": { "en": "Time (HH:MM:SS[.mmm])", "bg": "Час (ЧЧ:МИ:СС[.ммм])" },
  "saveButton": { "en": "Save", "bg": "Запис" },
  // ... 113+ more entries
};
```

Each key maps to an object with locale codes ('en', 'bg') and their corresponding translations.

```json
"build": "ng build && ANGULAR_BUILT=1 cordova build browser"
```

Translation data is already compiled as part of the TypeScript module.

## Runtime System

### I18nService (`src/app/services/i18n.service.ts`)

**Key Properties:**
- `currentLocale: Signal<string>` - Current active language (en, bg)
- `translationsForLocale: Computed` - Translations for current locale

**Key Methods:**
- `translate(key: string): string` - Get translated text or key if not found
- `setLocale(locale: string): void` - Change language and persist to localStorage
- `getCurrentLocale(): string` - Get current locale code
- `getSupportedLocales(): string[]` - Returns ['en', 'bg']
- `getLocaleLabel(locale: string): string` - Returns "English" or "Bulgarian"

**Initialization Logic:**
1. Check localStorage for saved preference (`locale` key)
2. If not found, detect from browser language
3. Default fallback: Bulgarian ('bg')

**localStorage Persistence:**
- Key: `'locale'`
- Value: 'en' or 'bg'
- Persists across browser sessions

### Component Usage

**Inject I18nService:**
```typescript
export class MyComponent {
  readonly i18n = inject(I18nService);
}
```

**In Templates:**
```html
<!-- Simple text -->
<h1>{{ i18n.translate('dashboardTitle') }}</h1>

<!-- Attributes -->
<button [attr.aria-label]="i18n.translate('saveButton')">Save</button>

<!-- Conditional -->
<span>{{ isEditMode ? i18n.translate('editTransaction') : i18n.translate('addTransaction') }}</span>

<!-- With dynamic content -->
<p>{{ i18n.translate('parsedTransactions') }}<strong>{{ count }}</strong></p>
```

## Why This Approach?

### Advantages
✅ **Simplicity** - All translations in one TypeScript file
✅ **No external tools** - No XLIFF parsing or code generation needed
✅ **Type safety** - Full TypeScript autocomplete for keys
✅ **No page reload** - Language switching using Angular Signals
✅ **Translations at build time** - All data bundled in the app
✅ **Small footprint** - ~1KB gzipped for 113 keys

### How It Works
1. Developer edits `translations.generated.ts` directly
2. TypeScript compiler includes it in the app bundle
3. I18nService imports and uses it at runtime
4. Components call `i18n.translate(key)` in templates
5. Current locale from localStorage determines which translation is shown
6. Language changes via `i18n.setLocale()` update the Signal

## Common Tasks

### Build and Deploy
```bash
npm run build
```
Automatically includes all translations in the compiled app.

### Add New Language
Example: Adding French ('fr')

1. Edit every entry in `translations.generated.ts`:
   ```typescript
   "formLabelDate": { "en": "Date", "bg": "Дата", "fr": "Date" },
   "formLabelTime": { "en": "Time (HH:MM:SS[.mmm])", "bg": "Час (ЧЧ:МИ:СС[.ммм])", "fr": "Heure (HH:MM:SS[.mmm])" },
   ```

2. Update `I18nService.getSupportedLocales()`:
   ```typescript
   getSupportedLocales(): string[] {
     return ['en', 'bg', 'fr'];
   }
   ```

3. Update `I18nService.getLocaleLabel()`:
   ```typescript
   getLocaleLabel(locale: string): string {
     const labels: Record<string, string> = {
       'en': 'English',
       'bg': 'Bulgarian',
       'fr': 'Français',
     };
     return labels[locale] || locale;
   }
   ```

4. Rebuild: `npm run build`


## Best Practices

1. **Keep keys descriptive** - Use camelCase like `formLabelDate`, not just `label`
2. **Group related keys** - Use prefixes like `form*`, `button*`, `error*`
3. **Always provide all locales** - Every key must have entries for 'en' and 'bg' (and any other supported locale)
4. **Use aria-labels and titles** - Make buttons and interactive elements accessible with `i18n.translate()`
5. **Test both languages** - Always verify translations display correctly after changes
6. **Keep it simple** - If a template gets complex with translations, consider extracting logic to the component

## Migration from Other i18n Systems

If migrating from `ng extract-i18n` or other systems:

1. List all current translations
2. Add them to `translations.generated.ts` in the format shown above
3. Delete old translation files (XLIF, JSON, etc.)
4. Update components to use `i18n.translate()` in templates
5. Update components to inject `I18nService`
6. Rebuild and test
